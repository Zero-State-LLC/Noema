# Code mode for the Noema repos

Agents call tools by writing short Python scripts against typed wrappers,
instead of loading every tool definition and passing every result through the
conversation. This follows Anthropic's
[Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp),
adapted to Noema's rules. Standard library only, Python ≥ 3.11, nothing to install.

```text
codemode/
├── run.py                 sandbox runner: every script goes through it
├── search_tools.py        find tools and skills by keyword (names → descriptions → source)
├── gen_wrappers.py        regenerate MCP wrappers from a server's tools/list
├── config.json            servers, repos, sandbox allow-lists
├── runtime/
│   ├── mcp.py             MCP client (streamable HTTP + stdio)
│   ├── gh.py              GitHub REST via `gh api`
│   ├── policy.py          repo policy per tool (Cloudflare read-only)
│   ├── privacy.py         PII and secret tokenizer + vault
│   ├── guard.py           audit-hook sandbox
│   ├── flow.py            retry, poll_until
│   └── shape.py           pick, count_by, table, grep_log
├── servers/
│   ├── cloudflare_api/    docs, execute, search, whoami   (MCP, generated)
│   └── github/            11 tools: issues, PRs, checks, runs, jobs, logs, commits, comment
├── skills/
│   ├── ci_failure_digest/ why did CI fail: failing tests from 100 KB+ logs
│   └── ci_watch/          wait for CI on repo:branch pairs or every open PR
└── .work/                 gitignored scratch, vault and temp files
```

## The rules

1. **Tools are files.** `servers/<server>/<tool>.py` holds one tool, with its
   one-line description as the first line. MCP servers are generated by
   `gen_wrappers.py`. GitHub wraps `gh api` REST, the repos' declared tracker
   interface (`docs/agents/issue-tracker.md`).
2. **Search, then read only what you need.** Run
   `python3 codemode/search_tools.py <words>`. Add `--full` only for the one or
   two tools you will call.
3. **Filter big data in code.** Issue lists, check runs and job logs stay in
   the script. Use `runtime/shape.py` and print only the rows or fields the
   task needs. Output over 12,000 characters is cut.
4. **Loops, retries and polling live in code.** Use `flow.retry`,
   `flow.poll_until` or `github.wait_for_checks`. Don't make repeated tool
   calls through the conversation.
5. **Personal data and secrets never reach the context.** The runner
   tokenizes everything a script prints:
   - Emails, phones and registered names become `[EMAIL_1]`, `[PHONE_1]` and
     `[NAME_1]`. The mapping is kept in `.work/vault.json`, and `mcp.call_tool`
     and `gh.api` map placeholders back only when sending to a tool.
   - Tokens, JWTs (including Admin), keys, passwords and cookies become
     `[SECRET]` and are never stored.
   - Public writes never map placeholders back. `comment_on_issue` refuses
     them.
   - Secret env vars are removed from `os.environ` before the script runs.
6. **Save what works.** Put a working, reusable script in
   `skills/<name>/` with a `SKILL.md` (see `skills/README.md`). Check skills
   before writing new code; `search_tools.py` lists them first.

**Sandbox.** `run.py` starts a child Python (`-I -B`) with a scrubbed
environment and installs `runtime/guard.py`:

- reads are limited to this repo and the Python installation;
- writes are limited to `codemode/.work` and `codemode/skills`;
- subprocesses are limited to `gh` and read-only `git` subcommands;
- the network is limited to configured MCP hosts;
- `os.system`, `exec`, `fork` and `ctypes` are refused.

This blocks accidental reach outside the project. It is not a boundary
against hostile code.

## Use it

```bash
python3 codemode/search_tools.py failed ci log
python3 codemode/run.py codemode/skills/ci_failure_digest/ci_failure_digest.py
python3 codemode/run.py -c '
from codemode.servers.github import list_issues
from codemode.runtime.shape import count_by
issues = list_issues()                      # open issues on the board (Noema-Specs)
print(len(issues), "open;", count_by(issues, lambda i: [l["name"] for l in i["labels"]])[:6])
'
```

Put longer scripts in `codemode/.work/` (gitignored) and run
`python3 codemode/run.py codemode/.work/task.py`.

## Noema-specific boundaries

- **Cloudflare is read-only.** `runtime/policy.py` refuses `execute` code
  whose `method:` is not a literal `GET` or `HEAD`. Deploys go through the
  dispatch-only pin workflow, and only when the user says **deploy**
  (`AGENTS.md`). Treat the policy as a seatbelt: the real boundary is a
  read-only token (`CLOUDFLARE_API_TOKEN`) or read-only OAuth scopes.
- **No world surface.** Code mode never sends `/v1/command`, `/play/action` or
  Durable Object `/command`, and never plays `world-01`. Agents inhabit only
  through `noema-client`.
- **Graft and Trail stay as they are.** They already provide progressive
  disclosure for code context.
- **Writes default to dry run.** Board updates are pre-authorized by the
  standing grant, but pass `dry_run=False` deliberately.
- **Writes follow the agent state.** `run.py` reads the current state from
  `.agents/machine.py`. Every GitHub write is mapped to a machine action
  (`docs_board`, `pr`, `merge`, `branch`, `delete`, `prod_change`) and refused
  unless the current state allows it. For example, nothing is written while
  the state is `STOPPED` or `AWAITING_USER`. Unmapped writes are refused
  outright.

## Add or refresh a server

1. Add it to `config.json` under `servers`. Use `"transport": "http"` with a
   `url` and an optional `token_env`, or `"transport": "stdio"` with a
   `command` and `args`; a stdio command is added to the exec allow-list.
2. Run `python3 codemode/gen_wrappers.py <server>` with auth available. This
   writes one wrapper per tool and refreshes `tools.snapshot.json`.
3. Put any repo policy in `runtime/policy.py`, never in generated files.

The checked-in Cloudflare wrappers were generated from
`servers/cloudflare_api/tools.snapshot.json`, which records the published tool
surface of `cloudflare/mcp`. Regenerate them live once a token is configured.

Tests: `python -m pytest tests/test_codemode.py -q`.
