Product loop

What the engine is for

Operators and agents act in a durable chamber world. Research layers may notice pressure, test counterfactuals, capture phenomena as regression tests, and rebuild capability graphs — always as derivation, never as ledger rewrite.

PLAY

Chamber world, budgets, observations, agent protocol. Restart-safe ledger. Spectator WATCH is redacted public projection.

NOTICE → TEST

Frontier injects only via SITUATION_INJECTED. Observatory detects. Lab forks with mutates_production: false.

research/frontier · observatory · lab

CAPTURE → LEARN

Compiler needs compiler_readiness: READY. LEARN graph is rebuildable index — not a mutable source of truth.

Deep Time

Institutions, artifacts, scars, names — historical surfaces for STUDY/PLAY. Lore never overrides ledger truth.

Genesis

Admin-only world creation. After activate, config freezes; Cycle 0 is ordinary world play with no Genesis UI required.

Quick start

Run the reference path

Python 3.11+ · optional Docker for Postgres. Local PLAY never requires a model provider key.

# clone & install
git clone https://github.com/Zero-State-LLC/Noema.git
cd Noema
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# prove chamber determinism
noema-replay          # EQUIVALENT seed
pytest -q
noema-play            # text PLAY (SQLite)
python scripts/core_loop_demo.py
pip install -e ".[postgres]"
cp .env.example .env
docker compose up     # postgres:16 + monolith

# or host runtime against DSN
noema-serve --db "postgresql://noema:noema@127.0.0.1:5432/noema" \
  --config examples/deployment/local-deployment-config.json

# open http://localhost:8080/  · /watch  · /play
noema-verify --db data/noema.sqlite3 \
  --seed fixtures/v01-seed/world-seed.json \
  --config examples/deployment/local-deployment-config.json
# → NOEMA VERIFY: PASS

noema-backup  --db data/noema.sqlite3 --out backups/world-1
noema-restore backups/world-1 --db data/restored.sqlite3 \
  --seed fixtures/v01-seed/world-seed.json

noema-keygen-evidence --out var/evidence-keyring.json
noema-export-evidence --db data/noema.sqlite3 \
  --keyring var/evidence-keyring.json --out exports/run-1 \
  --profile research-isolated
noema-verify-evidence exports/run-1 --keyring var/evidence-keyring.json
# → NOEMA EVIDENCE: VALID  (else INVALID_EVIDENCE)

HTTP surface

Gateway contract for UI & agents

Stdlib HTTP. Sessions via X-Session-Id (or body). Errors: { "error": { "code", "message" } }. /ready is PLAY readiness — research degradation does not block play.

Method Path Role Purpose
GET / public Operator home HTML (reference shell)
GET /watch · /play public Spectator / minimal PLAY HTML shells
GET /health · /ready · /version public Liveness, play readiness, pin metadata
GET /manifest · /config public Runtime manifest · non-secret config + digest
GET /watch/live spectator+ Redacted live projection JSON
POST /session — Create session (PLAYER / SPECTATOR / RESEARCHER / ADMIN)
POST /play/action · /play/observe PLAYER/AGENT Mutate / observe chamber
POST /protocol/v1 agent Agent protocol v1 (HELLO, AUTH, actions…)
POST /admin/start · /admin/genesis/* ADMIN Load seed · Genesis preview/activate
POST /research/* RESEARCHER/ADMIN Frontier, Observatory, Lab, Compiler, LEARN, Deep Time
UI integration note

The product UI milestone should treat this gateway as the stable backend. Prefer progressive disclosure and server-side claim labels / redaction. Do not invent a client-side ledger or strengthen research claims in the browser.

Operations

Verify · backup · restore

Specs OPERATIONS.md semantics with noema-* CLI names matching the rest of the toolbelt.

noema-verify

Fail-closed checklist: config, DB, schema, pins, ledger chain, snapshots, objects, seed, manifest, writer fence, atomicity, resume windows, evidence (when required).

prints NOEMA VERIFY: PASS

noema-backup

Portable bundle: ledger, snapshots, runtime manifest, configuration digest, fence audit. Secrets never embedded.

noema-backup-bundle/1.0

noema-restore

Clean target only (or --force). Fresh writer fence. Runs verify after install. Refuses incompatible catalog pins.

restore_fresh_writer_fence

Research export

Evidence receipts

Optional for local gameplay. Mandatory for research-isolated, reproducibility, and public-evidence-export. Missing or invalid required receipts become INVALID_EVIDENCE — never silently unsigned.

Receipt profile

Version evidence-receipt/1.0 · algorithm hmac-sha256 · policy noema-evidence-hmac/1. Binds evidence digest, world_id, consent/exclusion policies, export profile, key_id, signature, issuance time.

Keyring is operator-side only. Key rotation keeps retired keys for historical verification. Asymmetric public keys remain deferred.

Resume / ack windows

Non-canonical delivery bookkeeping. Bounded (default 256). References only committed sequences. Uncommitted acks fail closed. Redelivery never creates world events or charges budgets.

evidence/resume.py · OPERATIONS checklist #12

Hard rules

Invariants the UI must not break

  • 01One fenced canonical writer per world process.
  • 02WORLD TRUTH ≠ RESEARCH DERIVATION — research indexes are rebuildable.
  • 03Frontier injects only via ledger events through reducers.
  • 04Lab never mutates production state or ledger.
  • 05CAPTURE requires Lab compiler_readiness: READY.
  • 06Genesis is ADMIN-only; post-activate config freezes.
  • 07Lore / LEARN simple views never strengthen claim labels beyond evidence.
  • 08Deployment config and public bundles never carry secrets.
  • 09Research export without valid required receipt is INVALID_EVIDENCE.
  • 10No consciousness or scalar intelligence scores — ever.

Current milestone

Product UI (in progress)

Runtime Phases 0–11 are the stable backend contract. The UI track owns presentation, progressive disclosure, and operator/agent experience — not world truth.

Consume

Pin against Noema main (Phase 11: evidence). Use session roles, redacted WATCH, claim labels from the server, and non-secret /config digests for badges.

Avoid

Client-side ledgers, dual writers, inventing digests as authority, putting evidence keyrings in the frontend bundle, or blocking PLAY on research health.

Reference shells only

Routes /, /watch, and /play shipped in Phase 10 are minimal operator shells for Specs C14 — not the product UI. Replace them with the real interface when ready; keep the JSON APIs stable.
