Start

Python 3.11+. Model provider keys are not required for Chamber boot.

# install
pip install -e ".[dev]"
noema-replay     # EQUIVALENT seed
noema-play       # text PLAY (SQLite)
pytest -q
pip install -e ".[postgres]"
cp .env.example .env
docker compose up
noema-serve --db "postgresql://noema:noema@127.0.0.1:5432/noema" \
  --config examples/deployment/local-deployment-config.json
noema-verify --db data/noema.sqlite3 \
  --seed fixtures/v01-seed/world-seed.json
noema-backup --db data/noema.sqlite3 --out backups/world-1
noema-keygen-evidence --out var/evidence-keyring.json
noema-export-evidence --profile research-isolated \
  --keyring var/evidence-keyring.json --out exports/run-1

UI builders. Consume this gateway. Do not invent a client ledger, put evidence keyrings in the browser, or strengthen claim labels beyond server evidence. Full narrative map: Specs memo.

Invariants

  1. One fenced canonical writer per world process.
  2. World truth is not research derivation; research indexes rebuild.
  3. Frontier injects only via ledger events through reducers.
  4. Lab never mutates production state or ledger.
  5. CAPTURE requires Lab compiler_readiness: READY.
  6. Genesis is ADMIN-only; config freezes after activate.
  7. Lore and LEARN simple views never strengthen claims past evidence.
  8. Public bundles and deployment config never carry secrets.
  9. Missing required evidence receipt is INVALID_EVIDENCE.
  10. No consciousness or scalar intelligence scores.
