`worker.fetch`, actual JWT resolution/admission, actual internal `/command`
forwarding, `NoemaWorldDO.fetch`, world reducer and public projection handlers.

### Applicability and governed public-read limits

**WS stream-position stale/gap resynchronization: CANON_BLOCKED (reserved,
not a current missing hosted endpoint).** Accepted RFC-0003 §8
(`rfcs/RFC-0003-deterministic-contract-hardening.md:93–95`) and
`protocols/agent-protocol-v1.md:125–131` describe scoped delivery streams,
acknowledgements and bounded redelivery. The explicit current-hosted applicability
record at Specs `94286ca`,
`docs/PROTOCOL-CONFORMANCE-SWEEP-2026-08-24.md:68–76,82`, says
`RESUME_POSITION_EXPIRED` and `RESUME_POSITION_INVALID` are reserved because hosted
WS is request/response, with no server-initiated delivery stream. They become owed
only if separately approved server push lands. Runtime `protocol-ws.ts:11–15,210–329`
has principal/seal state, AUTH/HELLO and request/response dispatch, not delivery
cursor/window state. No new protocol, stream or fake resync URL was added.
This does not equate request retries or LOOK with delivery-position resync.

**Applicable settlement stale/gap resync: tested.**
`agent-http-do-resync.test.ts` exercises actual `/v1/command` -> World DO ->
`getWorldHead` / canonical settlement RPC transport. A completely local fetch fake
returns `SEQUENCE_GAP` and `REVISION_MISMATCH`, advances a fixture head, and verifies
`SETTLEMENT_RESYNC` restores its sequence/location/budget without accepting the
failed candidate. After a DO-instance restart, the identical idempotency key
re-evaluates against revision 7 and accepts one MOVE with one energy debit.
A further replay returns the accepted result and repeats the same settlement ID;
the fake RPC models SQL idempotent replay without accepting a second event.
This is real Worker/DO recovery logic over a fake database boundary, not proof of
Postgres transaction behavior. Only `https://settlement.invalid`'s two declared
REST paths are handled, with no actual network dispatch. The first test-authoring
expectation of no repeat RPC was corrected: replay may repeat the RPC while SQL
idempotency prevents a second accepted settlement. No production defect was inferred.

**Governed anonymous limits: mapped and tested, not a new quota.**
Specs `docs/SPECTATOR-ONBOARDING.md:15–18,22–28,35` limits anonymous reads to the
public projection, requires selected-Agent POV authorization and consent-gated
research, and forbids spectator world/ledger writes. Existing real private-message
coverage tests data exclusion. New projection tests compare ordinary public live/map
responses with anonymous `mode=research`, selected Player and `include_private`
query attempts, require identical public results without inhabit fields, and
compare the entire persisted world before/after reads for no write. Numeric
per-IP/per-request limits are deployment policy, not specified in these clauses.
No unsupported numeric quota is asserted or silently treated as validated.
