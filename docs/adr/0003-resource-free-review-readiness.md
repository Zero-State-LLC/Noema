# Review readiness is resource-free, using configuration-based assurance

The owner chose resource-free review readiness and an automatic-previews-off default for all Noema-runtime PRs over implicit preview provisioning. For a later separately authorized transition, fresh persisted off configuration and branch baseline before the event, inventory afterward, and stop/report on drift are the accepted assurance seam instead of demanding an absolute guarantee from an unavailable hosted webhook implementation. This preserves separately authorized preview work without turning a review action into a spending decision; it is an accepted operating policy, not proof of every provider event path.

## Consequences

- Preview creation must have separate bounded authorization; source-control review does not grant it.
- Transitions must use the pre/post evidence seam in [review/resource boundaries](../REVIEW-RESOURCE-BOUNDARIES.md); stale snapshots or unexplained drift must hold the action.
- Existing off configuration must be preserved rather than saved merely to prove it. Integration/repository settings, production behavior and billing changes need their own authority.
- Owner policy adoption, successful checks and eligible independent approval must remain separate. Target auto-squash does not enable a disabled repository setting or authorize merge under this docs-only work order.
- Privacy, isolated hosted acceptance and issue-level native/hosted gates remain unchanged. Provider defects or unseen webhook paths remain residual uncertainty, not permission to provision.
